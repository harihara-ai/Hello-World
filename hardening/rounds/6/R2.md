## Root causes behind the new findings

- RC-H residue: the change-folder rule is a deny list by extension and test-file name; the test runner decides what it
  collects, so any file type it runs by default slips through (R2-6-01).
- RC-I (new): the approved kit sits in a worktree the PR's own code can write. The recipe adds `../approved` and then
  runs the PR's tests in the same job, so the tests can rewrite the gates before they run (R2-6-02).

```
id: R2-6-01
severity: blocker
location: workspace/kit/gates/diff_scope.py (code_in_change_folder: `c.lower().endswith(CODE_EXT) or is_test_file(...)`)
evidence: d1 (pytest): change folder gets testing-notes.txt doctest patching TestCase.assertEqual; subtotal broken -> tests "5 passed", gate PASS, all gates true
problem: pytest collects `test*.txt` as doctests by default and runs them first (openspec/ sorts before tests/), so a non-code file in the change folder runs Python that hides a regression; neither CODE_EXT nor TEST_GLOBS (`test_*`) matches `testing-notes.txt`.
proposed_fix: Make the change folder an allow list: only `*.md` and `inputs/*.json` (plus `evidence/` attachments other than .txt) may change there; anything else fails code_in_change_folder.
confidence: high
```

```
id: R2-6-02
severity: blocker
location: workspace/kit/INSTALL.md "CI is the gate that counts" (`git worktree add ../approved` before the test step)
evidence: t1: test_cart.py rewrites ../approved/kit/gates/diff_scope.py, deletes tests/test_base.py, breaks subtotal -> PASS, all gates true; t0 (no rewrite) -> FAIL outside_scan
problem: The PR's tests run with write access to the approved kit, so any test in the approved scan can switch off any gate before gate_check runs; this needs no protected path, no change-folder file and no test-runner config.
proposed_fix: Add the approved worktree only after the test step, and have gate_check fail unless `git -C <kit worktree> status --porcelain` is empty; better, run gate_check in its own job that runs no PR code before it (red_check stays last).
confidence: high
```
