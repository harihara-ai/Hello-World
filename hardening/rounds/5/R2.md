## Root causes behind the new findings

- RC-H: the change folder is a free zone at done. diff_scope drops every path under it before the protected and
  impact-scan checks, so a code PR can add test-runner code or agent-steering files there (R2-5-02).
- RC-D residue: single use of a plan rests on an agent-written marker read by content, not by existence (R2-5-01).

```

severity: blocker
location: workspace/kit/scripts/gate_check.py plan_used (`elif from_base(base, ch + "/evidence.md")`); changectx.from_base (`if not text: return None`)
evidence: e1: code PR with zero-byte evidence.md -> PASS. u2: that PR merged; 2nd PR on CART-3 adds admin_override (returns -subtotal) -> PASS, no plan_used.
problem: from_base treats an empty or whitespace-only file as absent and done only checks that evidence.md exists, so one empty evidence.md keeps a plan reusable for any number of later code PRs (J01 single use defeated); a hotfix retro-spec plan (bug.md step 7) has no evidence.md either, so it is reusable once.
proposed_fix: Test existence, not content: plan_used when `git cat-file -e $BASE:<ch>/evidence.md` succeeds; bug.md step 7 puts evidence.md in the retro-spec plan PR.

```

## Minor notes

- Untracked files count as changed (`ls-files --others --exclude-standard`): a Python repo without `__pycache__/` in
  .gitignore fails its own CI with bytecode_added on the pycache the test step writes (first a0 run, before .gitignore).
  Fix: one INSTALL line (the test step must not leave untracked files) or drop `--others` in CI.
- playbooks/bug.md orders "Reproduce ... Record RED in evidence.md" (step 2) before G1 (step 4). In the two-PR flow the
  test cannot be in the plan PR (ready outside_scan), and an evidence.md merged with the plan makes the code PR fail
  plan_used. Reasoning from code; the merged-evidence case follows from the u1 run. Fix: move steps 2-3 after G1.
- J04's reach is wider than "tests for new code": any bug or story can add one new helper and import it from its test,
  so red_check passes by a load failure on base. No new finding (same root cause as J04); the limit text in
  kit/core/rules.md could say so.
