## Root causes behind the new findings

- RC-B (R2-3-01, 02): the CI recipe overlays the target's kit and policy onto the PR worktree instead of running a separate, pristine kit. Files the PR adds under kit/ survive the overlay and run; the PR's own edits to protected files are hidden from diff_scope and then merge.
- RC-C (R2-3-03, 04, 05): CI makes the coverage report, but the PR still controls what the numbers mean: the baseline value, which lines are instrumented, and whether a test asserts anything. RC-A moved down one level, from evidence files to the code and config that produce them.
- RC-D (R2-3-06): the G1-approved plan (spec, Type, impact scan) is re-read from the PR branch at done, and CI never runs `ready`.

```
id: R2-3-01
severity: blocker
location: workspace/kit/INSTALL.md "CI is the gate that counts" step 2 and 4
evidence: a2: PR adds kit/scripts/argparse.py (prints pass, exits 0) -> after step 2 `ls kit/scripts` still shows argparse.py; done rc=0 `{"stage": "done", "pass": true, "gates": []}`. With `-I -B`, kit/scripts/json.py instead -> every gate reports "planted" True. a1: PR lowers policy.yml, writes its own sign-off, guts kit/gates/diff_scope.py -> CI done PASS, `git diff --stat origin/main...feat` lists all three; they merge. n1: no sign-off on target -> "error: pathspec 'docs/ai/policy-signoff.json' did not match"; nothing restored.
problem: `git checkout origin/<target> -- kit ...` overwrites tracked paths but keeps files the PR added, and it makes the PR's edits to kit, policy and sign-off invisible to diff_scope, so CI either runs agent code as the gate or passes a PR that rewrites the floor on merge (and the step fails outright in repos without a sign-off file).
proposed_fix: Never overlay the PR tree: `git worktree add ../kit-base origin/<target>` and run `python3 -I -B -X pycache_prefix=$(mktemp -d) ../kit-base/kit/scripts/gate_check.py done --repo . --base $(git merge-base HEAD origin/<target>)`; gate_check already reads sign-off and baseline policy from base. Checked on a1: policy_guard loosened x2 and diff_scope protected_path x3 now fail.
confidence: high
```
