id: R3-3-01
severity: major
location: workspace/kit/gates/coverage.py:30 (`p["report"]` is one path); kit/INSTALL.md CI step 3
evidence: two-module Maven fixture, change in mod-a and mod-b, each with target/site/jacoco/jacoco.xml. Report=mod-a -> "mod-b/.../B.java is not in the report", 75.0% fail; report=mod-b -> 0.0% fail
problem: A monorepo or multi-module build (Maven, .NET solution, PHP packages) has several reports, so any change touching two modules fails and `current_total` is that one module's number.
proposed_fix: Accept `report` as a string or list (CI globs `**/jacoco.xml`), merge the parsed maps per file, and compute the total from summed covered/instrumented lines.
confidence: high

id: R3-3-02
severity: major
location: workspace/kit/gates/coverage.py:33,70 (baseline_total); kit/INSTALL.md step 3; scripts/gate_check.py payload_for
evidence: INSTALL step 3 says CI writes only the report path, yet `from_git` returns report_required without `baseline_total`; the value is read from inputs/coverage.json in the change folder (PR-controlled). `baseline_total: 0` can never trip overall_drop

id: R3-3-03
severity: major
location: kit/INSTALL.md CI step 2 (`git checkout origin/<target> -- kit kit.manifest.yml docs/ai/policy.yml docs/ai/policy-signoff.json`)
evidence: branch changes kit/x, then `git checkout main -- kit`; `git diff main -- kit | wc -l` -> 0
problem: Restoring those paths from the target makes the worktree equal the base there, so diff_scope (which diffs worktree against --base) can no longer see a PR that edits the kit or policy; only CODEOWNERS is left. The step also fails on the first PR when policy.yml or the sign-off does not exist on the target.
proposed_fix: Run `git diff --name-only origin/<target>...HEAD` for diff_scope before the restore (or pass the PR head SHA as the diff side), and make the restore tolerate missing paths.
confidence: medium

id: R3-3-04
severity: major
location: kit/INSTALL.md step 4 (`--base origin/<target>`); scripts/cov_import.py:119 `git diff base`
evidence: target gets commit changing src/o.py `x`->`y` after branching; `changed_lines('main')` -> {'src/a.py': {4}, 'src/o.py': {1}}; the merge-base gives only src/a.py
problem: Diffing against the target tip counts other people's later commits as this change's lines, so on any active monorepo the gate demands coverage for files the PR never touched (and diff_scope would flag them).
proposed_fix: Resolve `git merge-base HEAD origin/<target>` in gate_check when --base is given and pass that, or document `--base $(git merge-base ...)`.
confidence: high

id: R3-3-05
severity: major
location: workspace/kit/scripts/cov_import.py:56-58 (index pairing of sources and packages), :100-107 (match)
evidence: Cobertura packages [Api, Core], sources [/build/Core, /build/Api], both `Program.cs`: Api's hits=1 line lands under /build/Core/Program.cs; `match('src/Api/Program.cs')` -> None (report made in a container at /build, repo at src/)
