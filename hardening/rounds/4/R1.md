## New findings

```
id: R1-4-01
severity: blocker
location: workspace/kit/INSTALL.md "CI is the gate that counts"; core/policy.yml ready_gates
evidence: plan PR also adding src/Evil.php, CI `$GATE ready` -> rc=0, 4 gates pass
problem: the recipe runs `ready  # plan PRs` then `done` with no rule for which PR is which: run literally, every plan PR fails done (plan_not_approved); run as "ready for plan PRs", a plan PR carrying production code passes the required check, since ready has no diff_scope, coverage or red_check, and its merge counts as G1.
proposed_fix: gate_check picks the stage when `--change auto`: plan not in the base commit -> ready, and any changed path outside the change folder fails (a plan PR holds only the plan); plan in base -> done. The recipe becomes one `$GATE auto ...` line. Why not simpler: only gate_check knows the change folder and whether the plan is in the base; shell would re-implement both.
confidence: high
```

```
id: R1-4-02
severity: blocker
location: workspace/kit/scripts/gate_check.py:120; gates/coverage.py:29
evidence: no-folder PR deleting tests/LateFeeTest.php, stubbing tests/run_tests.py: "no change folder and no production code changed", rc=0
problem: the no-folder pass (meant for install, bootstrap, kit and policy PRs) counts test files as "not production", so an AI PR can delete tests, weaken asserts (also ran: `=== 2.00` -> `>= 0`, rc=0) or stub the runner with no gate run; and even with a change folder, coverage skips overall_drop when no production code changed, so test removal never fails.
proposed_fix: the no-folder pass needs every changed file to be PROTECTED or docs/*.md (no test or production file); coverage checks overall_drop whenever CI passed reports, not only when production code changed. Two condition changes, no new file or flag.
confidence: high
```
