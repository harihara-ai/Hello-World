## 2. Step counts

One story, ticket to merge (story.md plus the commands it calls):
- Playbook steps: 7. With sub-steps: intake 1, /learn 5 (only if a module has no card), /slice 6, /implement 5 per scenario (plus step 0), /gate 5, hand-over 1. About 25 Genie steps for a one-scenario story (7 + 6 + 6 + 5 + 1).
- Human actions: 3 required (say "work on KEY"; merge plan PR; review and merge code PR). Plus 1 per open question and 1 /learn confirm when a module is new, plus the `/gate` sign-off ask (gate.md step 5) that duplicates the merge.
- Files the Genie writes per change: 10 (ticket, spec, impact, slices, 2 inputs JSON, status, evidence, metrics, gates JSON) plus the trace table in the PR.
- The human does nothing that a script could do. Weak spot: gate.md step 5 asks for a sign-off recorded in status.md, which is not proof (rules.md 5) and repeats the merge approval. Cost: one extra question per gate.

CI setup (team lead, once per repo):
- INSTALL Files: 5 steps (copy kit and manifest, copy commands, import line, prerequisites, merge and run /bootstrap).
- Protect: 1 step, but it means copying about 35 patterns into CODEOWNERS by hand.
- CI recipe: 8 lines to translate into the CI product (fetch, merge-base, worktree add, GATE variable, ready, test run on HEAD, test run on BASE, done with 3 flags), then mark required.
- Total: about 15 steps, 3 of them in a CI language the kit does not know.
- Doable by one script instead of the human: merge-base and worktree (setup), choosing ready vs done (base commit already says whether the plan is merged), the BASE test run (baseline_total is in the base `docs/ai/baseline.md`), and the CODEOWNERS lines (printed from PROTECTED).

## 4. Findings (cuts, ranked by value)

id: R4-4-01
severity: major
location: workspace/kit/INSTALL.md:31-33, workspace/kit/scripts/gate_check.py (--baseline-report), gates/coverage.py, .claude/commands/gate.md:1
evidence: "<the same on BASE (or reuse the target branch's last report) for ../out/base.xml>"
problem: The lead must run the whole test suite a second time on BASE and learn a second report path, although bootstrap already writes the overall coverage percent to `docs/ai/baseline.md` and gate_check accepts `--baseline-total`.
proposed_fix: Remove `--baseline-report` and the BASE run. gate_check reads baseline_total from `docs/ai/baseline.md` as it is in the base commit (`from_base`, same as policy and sign-off). Saves about 25 lines (INSTALL 2, gate_check 4, coverage.py baseline-report parsing about 12, gate.md 1, coverage tests) and one full test run per PR. Weakens: the overall-drop check (10.4 #5) compares to the last recorded baseline, not to this exact base commit, so a stale baseline.md gives false passes or fails; `/refresh` or a human keeps it current. Changed-line coverage (the part G05 and G01 closed) is unchanged, and the baseline still comes from the base commit so the agent cannot rewrite it in its own PR.
confidence: medium

id: R4-4-02
severity: major
location: workspace/kit/INSTALL.md:22-36
evidence: "$GATE ready                                  # plan PRs"
problem: The CI recipe asks the lead to wire two stages, a worktree and a merge-base by hand, but the base commit already says which stage applies (plan merged on base means done, otherwise ready).
proposed_fix: Add `--stage auto` (or make `ready` and `done` implicit when `--change auto`): done if the plan is on the base commit, else ready; ready must fail if production or test code changed (diff_scope no_production is already available). Then the recipe is: fetch, worktree, one gate_check line plus `--coverage-report` and `--test-cmd`. INSTALL CI block drops from about 15 to about 7 lines; lead steps from 8 to 4; net code about +8 lines in gate_check, so this is the one rank-2 change that adds a little. Floor guarantee: none weakened if the ready-with-code failure is added and tested; the stage is chosen from the base commit, which the agent cannot change. Without that check, a PR could dodge `done` by looking like a plan PR, so do not ship one without the other.
confidence: medium
